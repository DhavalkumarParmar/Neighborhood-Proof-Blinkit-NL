# Worked example — one SKU, end to end

**BEA-0001 · Aurvi 10% Niacinamide Face Serum · 30 ml · ₹449 (MRP ₹629)**
Viewed by the "grocery-only regular" shopper, served by the Alkapuri dark store
in Vadodara.

Path: `/p/BEA-0001?p=regular`

This is the "normal" state, and it is the best walkthrough because the product
is **good** — 9 returns out of 212 — and the card still surfaces a complaint.
That is the whole argument in one screen.

---

## Step 1 · Raw ledger rows

`data/ledger.json` holds 56,522 rows. Filtering to this SKU at this store gives
**212 rows** — one per household, at most one row per household per SKU per
store. Four of them, verbatim:

```json
{"household":"HH-VAD-00013","sku":"BEA-0001","store":"ST-ALK","daysAgo":6,"returned":true}
{"household":"HH-VAD-00198","sku":"BEA-0001","store":"ST-ALK","daysAgo":1,"returned":true,"review":"Okay for the price."}
{"household":"HH-VAD-00119","sku":"BEA-0001","store":"ST-ALK","daysAgo":24,"returned":true}
{"household":"HH-VAD-00360","sku":"BEA-0001","store":"ST-ALK","daysAgo":1,"returned":true}
```

Of the 212 rows: **9 returned**, **30 carry a review string**.

Dates are stored as `daysAgo` (0–29) rather than absolute dates, so the
"last 30 days" window is true whenever the demo is opened.

---

## Step 2 · Numbers computed in code

`lib/proof-core.ts` `getProof("BEA-0001", "ST-ALK")` counts rows. No model
involved.

| Field | Value | How it is derived |
|---|---|---|
| `households` | **212** | Size of the `Set` of household IDs |
| `returns` | **9** | Rows where `returned === true` |
| `returnRate` | **0.042453** → 4.2% | 9 ÷ 212 |
| `categoryReturnRate` | **0.064287** → 6.4% | All beauty rows network-wide: 796 ÷ 12,382 |
| ratio | **0.66** | 0.042453 ÷ 0.064287 |
| `verdict` | **"low"** | 0.66 < 0.75 → "low" |
| `widened` | **false** | 212 ≥ 30, so no widening |
| `scope` / `scopeLabel` | `"store"` / `"Alkapuri"` | Store-level scope held |
| `reviews` | **24 strings** | 30 available, capped at `MAX_REVIEWS` |

---

## Step 3 · What was sent to the model

Only the review strings, plus the counts as read-only context. Returners are
listed first so a complaint can never be trimmed away — of 24 sent, **11 mention
the pump**:

```
- Product is good but the pump stopped working in 3 weeks.        ← ×8 in the list
- Serum is fine, packaging is the problem. Pump gave up very fast.
- Works well but the dispenser stopped pushing anything out.      ← ×2
- Pump got stuck after two weeks of use. Rest is okay.
- Texture is light and it absorbs fast.
- Mild, no irritation for me.
- Repeat order. Works for me.
- Value for money. Will order again.
- Delivered quickly and sealed properly.
- Okay for the price. / Average. Nothing special. / Delivery was fast.
```

The model was **not** asked what the return rate is, how many people bought it,
or whether the product is good. It was asked one thing: name the recurring theme.

---

## Step 4 · What came back

Live call, HTTP 200, **1.8 s**:

```
The product itself works well, but many buyers complained that the pump
dispenser breaks or stops working quickly.
```

Through `sanitise()`: contains no digit → **kept unchanged**.

```
┌──────────────────────────────────────────────┐
│ ● NEIGHBOURHOOD PROOF                        │
│                                              │
│ 212 homes near you                           │  ← code

│ The product itself works well, but many      │  ← model
│ buyers complained that the pump dispenser    │
│ breaks or stops working quickly.             │
│                                              │
│ ⛨ From real orders at your Alkapuri store,   │  ← code
│   last 30 days.                              │
└──────────────────────────────────────────────┘
```

Every line except the middle one is generated by code. The card renders the
numbers on the server immediately; the sentence is fetched afterwards by
`/api/summary` and dropped in when it arrives. If it never arrives, the card is
still complete.

---

## Why this example earns its slide

**A 4.2% return rate is a good product.** Beauty averages 6.4%. A star-rating
system would show four-and-a-half stars and stop.

This card says the product is fine, says the return rate is low *and* tells you
the pump breaks. All three at once. The complaint is not a warning to avoid the
product — it is the specific thing a shopper would want to know before buying,
and it is only visible because the prompt makes an only-positive summary a
failure and the retrieval layer puts returners' reviews first.
